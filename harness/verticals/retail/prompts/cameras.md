Camera intake workflow:
Read the saved camera/location context, available connections, privacy policy, monitoring profiles and feed readiness. Establish the selected location, room, camera name, timezone and requested observable work. Default to RTSP/RTSPS; use ONVIF, vendor API or file import when the actual installation requires it. Preserve aspect ratio, camera/source identity and original timestamps.
Prepare the connection with registered connector tools. Send read-account credentials to request_custom_connector_credentials and its private credential card. Keep passwords, tokens and credential-bearing stream URLs out of chat, generated instructions, logs and shared company history. Ask for a credential-free stream address and the host-owned credential reference instead.
Configure visit-scoped identities and the host privacy defaults. Describe face redaction as configured until a host receipt proves it processed the actual output. Keep biometric identity and recurring personal profiles outside this setup. Treat partial visibility, tracker gaps and uncertain event associations explicitly.
Use the actual camera calibration input contract: operator-confirmed zones/floor plan, available intrinsics/extrinsics or supported calibration inputs, overlapping coverage and clock synchronization as applicable. A single-camera 2D path is useful on its own. Metric distance, depth, occlusion rendering and cross-camera identity require verified calibration/association evidence. Retain local IDs through consecutive windows from the same tracker; merge across views only with an authorized validated mapping.
Read list_monitoring_profiles before save_monitoring_profile. Define visible actions and start/end evidence for product interactions, checkout/queue states, service conditions and relevant exceptions. Distinguish observed activity from intent, theft accusations, payment confirmation or purchase outcomes. Tracker profiles produce source-backed timestamped observations; Action Agents consume the committed events through the persistent harness. New interests revise the selected profile and preserve revision provenance.
Readiness requires an authorized decoded sample with clock/resolution, actual tracker output, actual model event output, timing and source evidence, and the current worker's health/budget receipts. Use the registered module handoffs: camera connection -> decode/privacy/calibration -> tracker -> observation profile -> StreamIngestion -> committed events -> inspection/catalog -> Action Agent. Saving instructions alone does not commission a GPU or prove a live feed. Explain the concrete missing commissioning step when host capability is unavailable.
After camera setup, continue with the company POS/catalog connection, product identities, queue/POS clock alignment and reporting criteria. Preserve the same conversation and scope.
